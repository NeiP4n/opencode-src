# core/v1 — configuration schemas of the previous format and their transfer into the current format

## What's In This Folder

The subfolder `config/` with 16 files. All of them, except `migrate.ts`, declare Effect Schema
for the settings of the old format; `migrate.ts` translates the old
format into the current one. The idea: users have the configs of an old
version on disk, and the core is able to read them and bring them to the new field names.

## Key Files

- `packages/core/src/v1/config/config.ts` — the root schema `Info` of the previous
  format: all the sections from `shell` to `experimental`.
- `packages/core/src/v1/config/migrate.ts` — `migrate`, `migrateAgent`,
  `migrateMcp`, `migrateProvider`, `migrateModel`, `commands`,
  `normalizeAction`, `providerID`.
- `packages/core/src/v1/config/agent.ts` — the schema of an agent plus normalization:
  `tools` turns into `permission`, `maxSteps` into `steps`.
- `packages/core/src/v1/config/permission.ts` — `Action`, `Object`, `Rule` and
  the normalization of a string into an object `{"*": value}`.
- `packages/core/src/v1/config/mcp.ts` — `Local`, `Remote`, `OAuth`.
- `packages/core/src/v1/config/provider.ts` — `Model` and `Info` of the provider:
  prices, limits, modalities, variants.
- `packages/core/src/v1/config/provider-options.ts` — the parsing of `options` into
  `settings`, `headers` and `body`.
- `packages/core/src/v1/config/lsp.ts` — `builtinServerIds` (36 servers) and the
  filter `requiresExtensionsForCustomServers`.
- The rest: `attachment.ts` (the limits of the pictures), `command.ts`,
  `formatter.ts`, `layout.ts`, `plugin.ts`, `server.ts`, `skills.ts`,
  `error.ts`.

## Important Details

- The schemas are normalized through `decodeTo`: `agent.ts` and `permission.ts` at
  decoding transform the value, at encoding they let it pass through
  (`SchemaGetter.passthrough({ strict: false })`), so that the extra fields on the reverse
  write are not lost.
- In `agent.ts` the keys outside the known set (`name` plus the fields of the schema)
  are carried over into `options` — that is how the arbitrary request parameters were hidden.
- The order of resolving the permissions of an agent: first the object from `tools` (`true` gives
  `allow`, `false` gives `deny`), where `write`, `edit` and `patch` are written into one
  field `edit`, then the explicit `permission` is laid on top. The explicit rule
  always wins.
- `permission.ts` lists the known keys (read, edit, glob, grep, list,
  bash, task, external_directory, question, webfetch, websearch, lsp,
  doom_loop, skill), but passes through any others via `StructWithRest`.
- The order of the permission keys in the config is kept when parsing
  (`propertyOrder: "original"`), because the priority of the rules depends on it;
  `migrate.ts` reads the same way, with `onExcessProperty: "ignore"`.
- The renaming of actions (`normalizeAction`): `write` and `patch` into `edit`,
  `task` into `subagent`, `bash` into `shell`. The other names do not change.
- `autoupdate` is translated into `update`: `false` into `disable`, `"notify"` into
  `notify`, `true` into `auto`. `autoshare` in the absence of `share` gives
  `share: "auto"`.
- Simple renames: `snapshot` into `snapshots`, `attachment` into `media`,
  `command` into `commands`, `plugin` into `plugins`, `reference` into `references`.
  A plugin of the kind `["package", {options}]` becomes `{ package, options }`.
- The permission rules are collected into a flat array `{ action, resource, effect }`:
  the old `tools` gives rules by actions with the resource `*`, the `permission` fields —
  by keys, a string rule expands into the resource `*`. Order:
  first `tools`, then `permission`.
- `enabled_providers` expands into a denial on `*` plus permissions on
  every listed provider; together with `disabled_providers` it goes into
  `experimental.policies` with the action `provider.use`. The section `experimental`
  is not carried over at all if there is neither `subagent_depth` nor lists of providers.
- A model string is accepted only in the form `provider/model`
  (the regular expression `^[^/#]+\/[^#]+$`), everything else is discarded silently.
- Agents from the old field `mode` are added to the agents from `agent` with a
  forced `mode: "primary"`; on a match of names the record from
  `agent` wins, because it goes second. `small_model` becomes the model of the `title` agent.
  A color from the theme set is replaced with `#aaaaaa`.
- The section `compaction` is carried over partially: `auto` and `prune` directly,
  `preserve_recent_tokens` into `keep.tokens`, `reserved` into `buffer`; the field
  `tail_turns` is not carried over. Skills: `paths` and `urls` are merged into one
  array.
- MCP servers: a record of the form `{ enabled }` without `type` is discarded, `enabled`
  becomes `disabled` with the reverse meaning. One timeout turns into a pair
  `{ catalog, execution }` with the same value; `experimental.mcp_timeout`
  is carried over as a fallback.
- The OAuth fields are renamed from camel case to snake case: `clientId`
  into `client_id`, `clientSecret` into `client_secret`, `callbackPort` into
  `callback_port`, `redirectUri` into `redirect_uri`. The value `false`
  turns into a falsy one via `&&` and simply disappears.
- The provider names are renamed (`providerID`):
  `azure-cognitive-services` into `azure`, `google-vertex-anthropic` into
  `google-vertex` — with a note that these are only the unambiguous cases. If
  there is both the old and the new name, the record under the old one is discarded. The field `api`
  of the provider becomes `baseURL` in the settings.
- For `azure-cognitive-services` the environment variable name
  `AZURE_COGNITIVE_SERVICES_RESOURCE_NAME` is removed from `env`, and in the
  absence of an explicit address the address with this substitution is substituted. For
  `google-vertex-anthropic` the provider-level package is removed, the needed package
  is prescribed to each model separately.
- Model: `id` into `modelID`, `tool_call` and the modalities into `capabilities` (they are not
  written at all if the flags are not set), `status: "deprecated"` into
  `disabled: true`, `interleaved` via `Model.compatibility`. The prices
  become an array: the base level plus, if present, the `context`
  level at 200000 tokens. The limits go through `int`, which cuts the fractional
  part and clamps into the limits of a safe integer.
- `error.ts` declares the error `ConfigInvalidError` with a path, a list of problems and a
  message via `NamedError.create`. `lsp.ts` keeps the list of the built-in
  servers right in the code with a note to keep it in agreement with the runtime; for
  any server outside the list `extensions` is mandatory.
- `attachment.ts` sets the limits of the pictures: width and height 2000, base64 not
  more than 5242880 bytes, the auto-reduction is on. `formatter.ts` and `lsp.ts`
  have the same shape of the setting: `false` switches off, `true` switches on
  the built-ins, an object switches on with the overrides.
- The root schema has a `$schema` for the config check by an editor; `layout.ts`
  keeps two values, but this field is marked as obsolete with a permanent
  `stretch`.

## Connections

- `@opencode/schema/config` — the current schema, the target of the transfer
  (`decodeInfo`/`encodeInfo`); `@opencode/schema/config/agent` and
  `@opencode/schema/config/reference` — its parts.
- `packages/core/src/provider.ts` — `Provider.aisdk` gives the package of the provider
  by the npm name.
- `packages/core/src/model.ts` — `Model.Capabilities.default()` and
  `Model.compatibility` for the transfer of the models.
- `packages/core/src/util/error.ts` — `NamedError.create`; `packages/core/src/schema.ts`
  — `PositiveInt`, `NonNegativeInt`, `DeepMutable`.
- `packages/core/src/image/photon.ts` — a consumer of the limits from
  `attachment.ts`; `packages/core/src/mcp/index.ts` and `client.ts` —
  consumers of the transferred MCP settings.

## Pitfalls

- Silent discarding: a model string not of the form `provider/model`, a server
  MCP without `type`, a provider under the old name in the presence of a new one, the OAuth
  values at `oauth: false` and empty sections disappear without a warning.
- The field `tools` in the old agent format must not be confused with the same-named
  root field: in an agent it turns into `permission`, in the root — into
  rules with the resource `*`.
- The order of the permission keys affects the priority, therefore it must not be changed when parsing
  — this is the only place where the order in the config is meaningful.
- `normalizeAction` touches only four names. A new name of the current format
  will not be translated, and the rule will stop matching.
- `mode` and `agent` are merged with the priority `agent`: the old agent from `mode`
  will get the `primary` mode regardless of the previous mark. `enabled_providers`
  gives a permission only for the listed ones, and the denial on `*` goes first:
  the order of the rules in the array matters for the priority.
- The removal of `AZURE_COGNITIVE_SERVICES_RESOURCE_NAME` from `env` does not mean that
  the variable is no longer needed: it is substituted into the address.
- In `provider.ts` the fields `timeout` and `headerTimeout` are declared with the same
  description text, although the first limits the request as a whole, the second —
  the waiting for the headers. The list of the built-in LSP servers is duplicated in
  the configuration and in the runtime: a divergence will give a server without extensions.
