# core/pty — псевдотерминалы: типы процессов, транспортные помощники и одноразовые тикеты подключения

## Что в папке

Шесть файлов и ни одного сервиса-владельца терминала: только типы, три
рантайм-адаптера спавна, протокол кадров для вебсокетов и сервис одноразовых
тикетов. Доменный сервис PTY живёт вне папки и не зависит от транспорта, а
маршруты сервера переводят `Pty.attach` в вебсокеты через помощники отсюда —
поэтому все поверхности говорят по одному протоколу.

## Ключевые файлы

- `packages/core/src/pty/pty.ts` — чистые типы: `Disp` (отписка), `Exit`
  (`exitCode` и необязательный `signal`), `Opts` (`name`, `cols`, `rows`, `cwd`,
  `env`), `Proc` (`pid`, `onData`, `onExit`, `write`, `resize`, `kill`).
- `packages/core/src/pty/pty.bun.ts` — адаптер Bun: `spawn` из `bun-pty`.
  На Windows через `dlopen("kernel32.dll")` вызывается
  `SetConsoleCtrlHandler(null, 0)`, после чего библиотека закрывается.
- `packages/core/src/pty/pty.node.ts` — адаптер Node: модуль грузится через
  `createRequire(import.meta.url)` из переменной окружения
  `OPENCODE_NODE_PTY_PATH` либо из `@lydell/node-pty`.
- `packages/core/src/pty/pty.workerd.ts` — заменитель рантайма: `spawn` бросает
  «Pseudo-terminals are unavailable on the workerd runtime».
- `packages/core/src/pty/protocol.ts` — помощники кадров: `REPLAY_CHUNK`,
  `metaFrame`, `chunks`, `decodeInput`.
- `packages/core/src/pty/ticket.ts` — сервис `@opencode/PtyTicket`:
  `issue`, `consume`, `Scope`, `ConnectToken`, `make`, `node`.

## Важные детали

- Исходящие кадры — сырые куски UTF-8 терминала. Ровно один управляющий кадр:
  байт `0x00`, затем UTF-8 JSON с абсолютным курсором вывода после реплея,
  чтобы клиент смог продолжить с нужного места.
- `REPLAY_CHUNK` = 64 КиБ: реплей бывает на мегабайты, поэтому он режется на
  кадры ограниченного размера функцией `chunks`.
- `decodeInput` принимает строку, `Uint8Array` или `ArrayBuffer`; декодер
  `fatal: true`, и невалидный UTF-8 приводит к `undefined` — вход просто
  отбрасывается, а не бросает ошибку.
- Тикет: TTL по умолчанию 60 секунд (`Duration.seconds(60)`), ёмкость кеша
  10 000 записей. `issue` кладёт `Scope` (ptyID, каталог, workspaceID) в кеш под
  ключом `crypto.randomUUID()` и возвращает `expires_in` в секундах;
  `consume` удаляет запись через `Cache.invalidateWhen` и сверяет все три поля
  области действия.
- У тикет-кеша задана функция `noLookup`, которая умирает с сообщением «PtyTicket
  cache must be used via set/invalidateWhen, never get»: обращение к `get`
  считается misuse интерфейса, а не отсутствующим ключом.
- В `pty.bun.ts` Ctrl+C сбрасывается один раз до спавна оболочек: отсоединённый
  сервер стартует с проигнорированным Ctrl+C, и оболочки ConPTY это наследуют.
  Зарегистрированные обработчики при этом сохраняются.
- В `pty.node.ts` `useConptyDll` включается только на Windows и только внутри
  single-executable-приложения (`isSea()` из `node:sea`).
- `make(ttl)` экспортируется специально для тестов с коротким TTL; в
  продакшене используется `layer` с дефолтным TTL.

## Связи

- `pty.bun.ts`, `pty.node.ts`, `pty.workerd.ts` — три варианта одного модуля с
  одинаковым экспортом `spawn`; выбор варианта делает сборщик по суффиксу.
- `pty.ts` — единственный источник типов: адаптеры только реэкспортируют
  `Disp`, `Exit`, `Opts`, `Proc`.
- `pty/protocol.ts` описан как «Pty.attach к вебсокету», то есть используется
  маршрутами сервера, а не самим терминалом.
- `ticket.ts` зависит от схем `@opencode/schema/pty-ticket`,
  `@opencode/schema/pty`, `@opencode/schema/workspace` и от
  `makeGlobalNode` — сервис глобальный, не привязан к локации.
- Оболочки из `pty.bun.ts`/`pty.node.ts` — единственное место в папке, где
  нужен реальный процесс ОС.

## Ловушки

- Ни один файл папки не экспортирует сервис терминала: искать владельца
  `Pty.attach` нужно вне `packages/core/src/pty`.
- `opts.cwd` и `opts.env` в типах необязательны, но `name` обязателен — при
  вызове с объектом без `name` ошибка придёт уже из нативного модуля.
- `onData` и `onExit` возвращают `Disp`; если отписка потеряна, слушатель
  продолжит получать данные — хранить и вызывать `dispose` обязан вызывающий.
- Тикет одноразовый: повторный `consume` того же значения вернёт ложь, потому
  что `invalidateWhen` удаляет запись при первом же успешном изъятии.
- `metaFrame` всегда ставит `0x00` первым байтом — клиент обязан отличать
  управляющий кадр по этому байту, иначе он будет показан как текст терминала.
- На workerd любой вызов `spawn` — дефект, а не поддерживаемая ветка:
  терминалы в этой среде не работают вовсе.
