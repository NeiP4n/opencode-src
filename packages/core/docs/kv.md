# core/kv — таблица «ключ-значение» для служебного состояния

## Что в папке

- `sql.ts` — единственный файл: таблица `kv` на две колонки плюс временные метки.
- Логики чтения и записи в папке нет: она в корневом `packages/core/src/kv.ts`.

## Ключевые файлы

- `packages/core/src/kv/sql.ts` — `KVTable`.

## Важные детали

- Колонки: `key` — `text().primaryKey()`, `value` — `text({ mode: "json" })` с типом `KV.Value` и `.notNull()`, плюс `Timestamps` из `packages/core/src/database/schema.sql.ts`.
- Первичный ключ — сам ключ, поэтому запись уникальна по имени и обновление идёт через `replace` или `insert ... onConflictDoUpdate`, а не через выборку и вставку.
- Значение типизировано аннотацией `$type<KV.Value>()`, а не схемой Effect: проверка формы значения живёт в вызывающем коде.
- Поле называется `value`, а не `data`; читается в других таблицах пакета как `row.value`.

## Связи

- `packages/core/src/kv.ts` — потребитель таблицы; сервис общего назначения, который держат и другие подсистемы ядра.
- `packages/core/src/database/v1-migration.bun.ts` — второй потребитель `KVTable` по результату поиска по имени таблицы: во время миграции прошлых версий состояние переносится в эту таблицу.
- `packages/core/src/models-dev.ts` — использует `KV` для хранения кэша каталога моделей (`updatedAt`, `digest`, `body`), то есть большие JSON-объекты кладутся сюда же.
- `packages/core/docs/database.md` — общий слой доступа к базе, через который идёт работа с этой таблицей.

## Ловушки

- Тип значения навязан аннотацией: строка, записанная в таблицу вопреки `KV.Value`, не будет проверена ни при записи, ни при чтении.
- Ключ без версии и без пространства имён: два подсистемы, выбравшие одинаковый ключ, молча делят одну запись. Именно поэтому в `models-dev.ts` ключ включает хэш источника (`models-dev:catalog:<hash>`), а не только имя.
- `Timestamps` на таблице означает, что время создания и обновления есть, но никто в схеме не следит за их согласованностью — это делает код.
- `value` не имеет отдельной таблицы истории: перезапись значения не оставляет следов, поэтому кэш каталога моделей хранит рядом `digest` и `updatedAt`, чтобы не публиковать байт-в-байт тот же каталог.
