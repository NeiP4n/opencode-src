# core/tool — исполнение инструментов: схемы, права, чтение файлов и 16 встроенных инструментов

## Что в папке

Пять файлов поддержки и подпапка `plugin/` с 16 встроенными инструментами
(read, write, edit, patch, grep, glob, shell, question, skill, subagent,
webfetch, websearch, opencode, mcp-resource и вспомогательный file-diff).
Рядом лежит `AGENTS.md` с каноном папки и `patch.txt` — описание
инструмента patch, импортируемое как модуль.

## Ключевые файлы

- `packages/core/src/tool/runtime.ts` — мост между регистрацией и
  провайдером: `definition`, `execute`, `normalizeContent`,
  `normalizedName`, `effectiveName`, а также нормализация JSON Schema.
- `packages/core/src/tool/read-filesystem.ts` — чтение файлов, каталогов и
  медиа постранично: сервис `ReadToolFileSystem`, ошибки
  `BinaryFileError`, `MediaIngestLimitError`, `OffsetOutOfRangeError`,
  `PathKindError`, схемы `TextPage` и `ListPage`.
- `packages/core/src/tool/mcp.ts` — регистрация инструментов MCP-серверов
  как обычных, сервис `McpTool` с методом `flush`.
- `packages/core/src/tool/http-body.ts` — тело HTTP-ответа с жёстким
  лимитом байт.
- `packages/core/src/tool/html-markdown.ts` — конвертер HTML в markdown
  (658 строк, свой парсер поверх `htmlparser2`), функция
  `convertHTMLToMarkdown`, константа `MAX_MARKDOWN_BYTES`.
- `packages/core/src/tool/plugin/` — сами инструменты; `read.ts` ещё ищет
  `AGENTS.md` вверх по дереву, `patch.ts` применяет патч и умеет
  перемещение файла, `shell.ts` запускает команды в фоне, `subagent.ts`
  работает в дочерней сессии, `opencode.ts` даёт инструменты самой системы.

## Важные детали

- Лимиты чтения: `MAX_READ_LINES` = 2000, `MAX_READ_BYTES` = 50 КиБ,
  `MAX_MEDIA_INGEST_BYTES` = 20 МиБ, длина строки обрезается до 2000
  символов, чанк чтения `FIRST_CHUNK` = 256 КиБ.
- `MEDIA_MIMES` (png, jpeg, gif, webp, pdf) читаются целиком и отдаются
  base64, остальное — текстом. Бинарность определяется по наличию нулевого
  байта, а не по расширению.
- Постраничное чтение опирается на «веревку» (`TextNode` с весами по
  байтам и переносам строк): позиция строки ищется как порядковая
  статистика, без повторного декодирования.
- `runtime.ts` принимает три вида схем: Effect Schema, Standard Schema
  (`~standard`) и обычный JSON Schema. JSON Schema конвертируется через
  `JsonSchema.fromSchemaDraft07` или `2020-12` — выбор по полю `$schema` и
  наличию `definitions`.
- Перед отправкой модели JSON Schema упрощается: `allOf` схлопывается,
  локальные `$ref` разворачиваются, неиспользуемые `$defs` удаляются.
  Меняется только представление, не проверка. Рекурсивные ссылки не
  разворачиваются намеренно; при конфликте полей слияние идёт через
  `allOf`.
- `execute` на границе доверия приводит любую ошибку к `Tool.Error`: чужой
  типизированный сбой иначе проскочил бы мимо всех `catchTag` и оставил
  бы вызов незавершённым. Отказ пользователя и прерывание не трогаются.
- `normalizeContent`: строка становится текстовым блоком, пустой массив —
  текстом из вывода (JSON), непустой копируется как есть.
- `normalizedName` заменяет всё, кроме букв, цифр, `_` и `-`, на
  подчёркивание; `effectiveName` дополнительно склеивает пространство имён.
  Точе в пространстве имён заменяются на подчёркивания — иначе, чем в
  `tool/mcp.ts`, где та же задача решается регулярным выражением.
- Все инструменты кроме `opencode`, `mcp-resource` и `subagent` выключены
  из Code Mode опцией `codemode: false`; `session_move` наоборот
  `pinned: true`.
- `edit`, `write` и `patch` используют общее действие права `edit`, остальные
  — своё имя инструмента. Право проверяется **после** подготовки: у `edit`
  это чтение файла и подсчёт совпадений, у `shell` — разбор команды.
- `edit` ищет совпадение в три прохода: точное вхождение, затем с
  нормализацией Unicode (кавычки, тире, пробелы), затем построчное
  сравнение с обрезкой конца строки; совпадения третьего прохода
  непересекающиеся. Замена применяется с конца списка, чтобы смещения не
  разъезжались.
- `patch` применяется под блокировкой файлов, путь блокировки считается до
  исполнения эффекта; при ошибке сообщает, какие файлы уже изменены.
- `patch` скрывает `edit` и `write` для моделей семейства `gpt-`, кроме
  `oss` и `gpt-4`, а для остальных скрывает сам `patch`.
- `shell` по умолчанию даёт 120 секунд, фоновые команды без таймаута; в
  окружение ставятся `AGENT=1`, `OPENCODE=1`, `AI_AGENT`,
  `OPENCODE_SESSION_ID`.
- `subagent` проверяет глубину вложенности по
  `experimental.subagent_depth` (по умолчанию 1), запрещает агентов режима
  `primary` и требует, чтобы продолжаемая сессия была ребёнком текущей.
  Описание дополняется списком доступных подагентов через хуки сессии.
- `webfetch` отклоняет не-HTTP схемы, картинки и нетекстовые типы, таймаут
  30 секунд по умолчанию и максимум 120, повторяет запрос с другим
  User-Agent при ответе Cloudflare (403 с `cf-mitigated: challenge`).
- `websearch` без провайдера задаёт вопрос пользователю через форму: отмена
  даёт ошибку, «disable» отключает поиск, «random» запоминает выбор.
- `html-markdown.ts` ограничивает вывод `MAX_MARKDOWN_BYTES` = 5 МиБ и
  обрезает по границе байтов; при вложенности более 10000 тегов парсинг
  останавливается. Скрываются `script`, `style`, `noscript`, `iframe`,
  `object`, `embed`, `meta`, `link`, `template`, атрибуты `hidden`,
  `aria-hidden="true"` и всё внутри `head`. Таблица печатается
  Markdown-таблицей только при одинаковой ширине строк и без
  `colspan`/`rowspan`, иначе построчно. Глубина цитат не больше 8 уровней.

## Связи

- `packages/core/src/tool/AGENTS.md` — канон папки: правила регистрации,
  приоритет имён, `dispose`, запрет второго пути исполнения и запрет
  `catchCause` в листьях.
- `packages/core/src/tool.ts` (корень `src`) — владеет сервисом
  инструментов и их выполнением.
- `@opencode/ai` — `ToolDefinition` и `ToolFailure`;
  `@opencode/schema/tool` — типы `Info`, `Context`, `Content`, `Metadata`;
  `@opencode/schema/file-diff` — форма диффа.
- `@opencode/util/patch` — `Patch.parse`, `Patch.derive`, `Patch.joinBom`;
  `@opencode/util/bom` — работа с BOM.
- `packages/core/src/file-access.ts` — `resolve`, `authorizeRead`,
  `authorizeExternal`; `packages/core/src/file-mutation.ts` — `readText`,
  `write`, `withLock`, `syncTextBom`.
- `packages/core/src/shell.ts` и `shell/` (`parse.ts`, `select.ts`,
  `result.ts`); `packages/core/src/ripgrep.ts` — `grep` и `glob`;
  `packages/core/src/filesystem.ts` — `Entry`, `Match`, лимиты поиска.
- `packages/core/src/permission.ts`, `packages/core/src/form.ts`,
  `packages/core/src/job.ts`, `packages/core/src/session/subagent-job.ts`.
- `packages/core/src/codemode/tool.ts` — потребитель `definition` и
  `normalizedName` из `runtime.ts`.

## Ловушки

- Отказ пользователя и закрытие вопроса идут дефектами сквозь `mapError`:
  ловить их там нельзя, иначе модель получит «ошибку инструмента» вместо
  тихого завершения шага.
- У всех инструментов ошибка бронирования заворачивается в `Effect.orDie`:
  сбой регистрации роняет слой, а не возвращается модели.
- `edit` ищет `oldString` как подстроку, отступы новых строк пишет модель
  сама. Разрешение пути и чтение файла идут **до** проверки совпадения,
  поэтому ошибочный вызов всё равно платит за чтение.
- `edit` при нескольких совпадениях падает, но превью диффа к этому моменту
  уже отправлено в проверку права.
- `glob` сравнивает входной путь со строками `"undefined"` и `"null"` — это
  защита от подставленных моделью значений. `glob` и `grep` запрашивают у
  ripgrep `limit + 1`, чтобы отличить «ровно лимит» от «есть ещё».
- `grep` при пустом `pattern` падает на проверке схемы с особым текстом.
- `shell` запускает разбор команды и проверку прав до спавна процесса, а
  проверку существования каталога — сразу перед ним: одобрение может
  пережить удалённый каталог.
- Текст `BACKGROUND_INSTRUCTION` запрещает модели опрашивать завершение
  фоновой команды; похожие запреты есть в `subagent` и `websearch`.
- `subagent` при продолжении сессии с другим агентом модель переключает, а
  при том же агенте наследует от родителя.
- `read` подбирает имя, отличающееся только нормализацией Unicode, и
  добавляет найденные `AGENTS.md` как инструкции сессии; сбои этого поиска
  никогда не проваливают чтение.
- Форматирование в `write`/`edit`/`patch` вызывается **после** записи, а BOM
  восстанавливается отдельным чтением: если форматтер не сработал, на диск
  могла попасть другая кодировка BOM.
- В `write` и `edit` есть пометки о нереализованных шагах: события
  наблюдателя файлов, снимки и отмена изменений, уведомления LSP. Их нет —
  правка файлов не порождает событий и не откатывается.
