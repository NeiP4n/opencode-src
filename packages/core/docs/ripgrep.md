# core/ripgrep — где взять бинарник ripgrep: системный, уже скачанный или загрузка с GitHub

## Что в папке

Один файл `binary.ts`: сервис `@opencode/RipgrepBinary`, который один раз
находит или доставляет исполняемый файл `rg` и отдаёт его путь. Никакого
поиска по файлам здесь нет — только подготовка бинарника, чтобы поиск по
проекту работал без установленного пакета в системе.

## Ключевые файлы

- `packages/core/src/ripgrep/binary.ts` — единственный файл: namespace
  `RipgrepBinary` с `VERSION` = `15.1.0`, таблицей `PLATFORM`, сервисом
  `Service` и узлом `node`.

## Важные детали

- Порядок выбора бинарника: сначала `rg`/`rg.exe` в `PATH` (приоритет
  `Global.bin`), затем уже скачанный `rg` в `Global.bin`, и только потом
  загрузка с GitHub. Результат кешируется через `Effect.cached`, поэтому в
  пределах жизни слоя путь ищется один раз.
- Таблица `PLATFORM` перечисляет семь сборок: aarch64 и x86_64 для macOS и
  Linux (`tar.gz`), а также arm64, ia32 и x86_64 для Windows (`zip`). Для Linux
  выбран musl-сборка. Платформа без записи в таблице даёт явную ошибку
  `unsupported platform for ripgrep`.
- Архив скачивается с тега релиза BurntSushi/ripgrep в `Global.bin`, затем
  распаковывается во временный каталог с префиксом `ripgrep-`, копируется в
  цель и на не-Windows получает права `0o755`. Архив после распаковки
  удаляется, ошибка удаления игнорируется.
- Распаковка zip делается через `powershell.exe` или `pwsh.exe` (ищутся через
  `which`), tar.gz — системной командой `tar`. Обе команды требуют кода
  возврата 0, иначе в ошибку идёт текст stderr, stdout или сам код.
- В PowerShell-команду одинарные кавычки путей экранируются удвоением, а сам
  прогресс подавляется через `$global:ProgressPreference`.
- Исполняемый файл ищется по имени `rg.exe`/`rg` внутри распакованного
  каталога с версией и платформой; если его нет — ошибка «ripgrep archive did
  not contain executable».
- Пустой ответ загрузки считается ошибкой до записи файла: при нулевой длине
  байтов загрузка прерывается сразу.
- Запуск вспомогательных команд сделан вручную через `ChildProcessSpawner` с
  `extendEnv: true` и `stdin: "ignore"`, stdout и stderr собираются и код
  возврата читаются одновременно (`concurrency: "unbounded"`).

## Связи

- Зависимости узла: `FSUtil.node`, `Global.node`, клиент HTTP и
  `CrossSpawnSpawner.node`.
- Поиск файлов по содержимому живёт в `../ripgrep.js`, а потребитель пути
  бинарника — слой `filesystem/search.ts`, который выбирает между ripgrep и fff.
- `which` берётся из `../util/which.js` и получает дополнительный каталог
  `Global.bin`, поэтому установленный вручную `rg` из каталога данных виден
  так же, как системный.

## Ловушки

- Первая же попытка запуска скачивает файл из сети: без доступа к GitHub сервис
  падает, даже если где-то на машине есть рабочий `rg` — но только если тот не
  найден в `PATH` и в `Global.bin`.
- Для Linux берётся musl-сборка: на glibc-системах она работает, на
  нестандартных окружениях выбор не подстраивается под libc машины.
- Windows без PowerShell распаковать zip нечем — `findExecutable` вернёт
  пусто, и будет выбран `powershell.exe` по умолчанию, который может
  отсутствовать.
- `filepath` — это `Effect` с ошибкой в канале: вызывающая сторона обязана
  обработать отказ, а не считать путь гарантированным.
- Архив после распаковки удаляется, но во временном каталоге распаковки
  остаются копии; их убирает scope-финализатор `makeTempDirectoryScoped`.
