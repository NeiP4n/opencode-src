# core/codemode — выполнение инструментов как кода: каталог, инструкция, расширение fetch, инструмент execute

## Что в папке

Четыре файла: `catalog.ts` — сжатие каталога инструментов до лимита,
`instructions.ts` — инструкция для модели с этим каталогом, `web.ts` —
расширение с функцией `fetch`, `tool.ts` — сам инструмент `execute`,
который исполняет написанный моделью код и вызывает через него инструменты.

Смысл: вместо тысячи отдельных вызовов модель пишет JavaScript и
оркестрирует вызовы сама, а каталог инструментов попадает в инструкцию
только частично — с бюджетом символов.

## Ключевые файлы

- `packages/core/src/codemode/catalog.ts` — `summarize(inventory, options)`,
  `namespaceLine(namespace)`, внутренние `flatten`, `rankListings`, `cost`;
  схема `Tool` и типы `Namespace`, `Inventory`, `Summary`, `Options`.
- `packages/core/src/codemode/instructions.ts` — `render(catalog)`,
  `update(previous, current)`, `make(inventory?)`, внутренняя `prompt(hasMoreTools)`.
- `packages/core/src/codemode/web.ts` — `extension`, `display(args)`, локальный
  `fetch` с таймаутом 30 секунд.
- `packages/core/src/codemode/tool.ts` — `create(inventory, executeTool)`
  (собирает `Info` инструмента `execute`), `catalog(inventory)`,
  внутренние `runtime`, `renderTools`, `renderCatalog`, `formatResult`.

## Важные детали

- Стоимость строки в бюджете считается как `Math.round(длина / 4)` —
  четыре символа на токен. Бюджет по умолчанию `INLINE_BUDGET` = 2000,
  переопределяется опцией `budget`.
- Бюджет расходуется так: сначала все пространства имён (заголовок плюс
  закреплённые инструменты), затем по одному инструменту в пространстве за
  раунд, начиная с самых коротких строк. Пространство выбывает, когда
  следующий кандидат дороже остатка бюджета.
- Инструменты с `pinned: true` попадают в вывод всегда и не занимают
  конкуренцию: они пополняют `selectedListings` до расчёта остатка.
- Первая строка описания инструмента обрезается до 120 символов с многоточием
  и печатается комментарием `//` после сигнатуры. Пустое описание
  комментарий не добавляет.
- Имя пространства имён берётся из первой части `path` до точки
  (`tool.path.split(".", 1)[0]`), то есть группировка верхнего уровня.
- `Summary` различает `total` (сколько всего) и `shown` (сколько строк
  реально попало). Расхождение этих чисел — признак частичного каталога,
  и именно оно переключает формулировку инструкции.
- `namespaceLine` даёт три варианта подписи: полный (`5 tools`), частичный
  (`5 tools, 2 shown`) и пустой (`5 tools, none shown`); единственный
  инструмент всегда печатается как `1 tool`.
- В `instructions.ts` решается, показывать ли модели упоминание `search`:
  функция `prompt(hasMoreTools)` даёт два разных текста — при полном
  каталоге в тексте остаётся «The catalog is complete. Do not guess tool
  names.»
- При пустом каталоге (`total === 0`) инструкция прямо запрещает вызывать
  `execute` и предупреждает, что каталог может измениться.
- `update` сначала сравнивает полноту обоих состояний: если одно было
  полным, а другое нет, отдаётся полная замена. Дальше сравниваются
  описания пространств, затем строки инструментов, затем количества
  инструментов в пространствах.
- Дельта выбирается только если она **короче** полной замены
  (`delta.length < replacement.length`), иначе отдаётся полный каталог.
- В режиме частичного каталога удалённые инструменты печатаются через
  `toolExpression(path)` (имя в скобках), в полном режиме — как `path`.
- `make(inventory?)` без аргумента возвращает состояние `removed`:
  инструкция говорит, что инструментов Code Mode больше нет.
- `web.ts`: таймаут `TIMEOUT_MS` = 30 000 через `AbortSignal.timeout`, тело
  ответа сразу читается в байты (`response.bytes()`), и из них потом
  получаются `text()` и `json()`. Заголовки нормализуются в нижний регистр,
  `get` возвращает `null` при отсутствии.
- `display(args)` показывает для вызова `fetch` только метод и URL — метод
  по умолчанию `GET`, в верхнем регистре.
- `tool.ts`: описание инструмента `execute` — неизменяемый текст про
  недоступные импорты, файловую систему и таймеры, плюс правило вызова
  только по точным путям и сигнатурам из каталога, с сохранением
  bracket-нотации вида `tools.<ns>["tool-name"](input)`.
- Счётчики вызовов хранятся в `Ref`, а запись в журнал защищена
  `Semaphore` с однимpermit — параллельные вызовы не теряют строки.
- Журнал `toolCalls` показывается по порядку старта: индекс вызова
  запоминается в `WeakMap` по объекту вызова, поэтому второй хук находит
  свою же строку и меняет только `status`.
- Собранный `ExecuteOutput` возвращается сразу в трёх видах: `output`
  (структура), `content` (текст плюс файлы как data-URI) и `metadata`.
- Файлы из результата собираются в порядке вызова инструментов и
  поднимаются наверх в `files`; base64-данные берутся из `uri` только
  при префиксе `data:<mime>;base64,`, иначе часть игнорируется.
- `runtime` строит дерево `Node` (инструмент, пространство, потомки) и
  разруливает коллизию: запись в объекте не может быть одновременно
  инструментом и пространством, поэтому такой инструмент выносится в
  плоскую запись по полному пунктирному пути.
- `qualifiedName` добавляет префикс пространства из
  `registration.options.namespace`, а имя нормализует функцией
  `normalizedName` из `tool/runtime.ts`.
- `formatResult`: успех — значение (`JSON.stringify` с отступом 2, если не
  строка), ошибка — сообщение плюс подсказки `suggestions`, отфильтрованные
  от повторов (подсказка, уже содержащаяся в тексте ошибки, не печатается).
  Предупреждения и логи приклеиваются отдельными блоками `Warnings:` и
  `Logs:`.
- `catalog(inventory)` отмечает `pinned` по опции регистрации
  `options.pinned === true`, а не по данным каталога.

## Связи

- `@opencode/codemode` (отдельный пакет, 45 файлов по манифесту) — сам
  движок: `CodeMode.make`, `Tool.make`, `Namespace.make`, `Extension.make`,
  `toolError`, типы `Hooks`, `Result`, `DataValue`, а также
  `searchSignature` и `toolExpression`, которые печатаются в инструкцию.
- `packages/core/src/tool/runtime.ts` — `definition(registration)` и
  `normalizedName(registration)`: нормализация имён и приведение регистрации
  инструмента к описанию и схемам.
- `@opencode/schema/tool` — типы `Info`, `Context`, `Content`, `Result`,
  `Metadata`, `Error`, `Namespace`, отдаваемые в реестр инструментов.
- `packages/core/src/instructions/index.ts` — `Instructions.make`, `Key`,
  `diffByKey`, `removed`; ключ инструкции `core/codemode`.
- `CodeMode.Input` из пакета `codemode` — схема входных данных: объект с
  полем `code`.

## Ловушки

- В `catalog.ts` есть пометка в коде о том, что обход пространств имён пока
  не ограничен по размеру: при очень большом каталоге сумма заголовков
  пространств может превысить бюджет целиком, и полного каталога модель не
  получит.
- `remaining` считается вычитанием, поэтому при перерасходе уходит в
  отрицательные числа и цикл просто ничего не добавляет — ошибки не
  будет, инструментов в выводе окажется меньше ожидаемого.
- Бюджет тратят только инструменты, прошедшие `rankListings`: порядок
  выбора — по длине строки, а не по важности, кроме закреплённых.
- `make()` без инвентаря даёт `removed`, и `read` возвращает особое
  состояние, а не пустой каталог: разница видна в рендере.
- `update` сравнивает строки инструментов (`line`), а не сами объекты
  каталога, поэтому любое изменение сигнатуры или комментария
  считается изменением инструмента.
- Коллизия «инструмент и пространство под одним именем» разрешается
  выносом инструмента в плоскую запись по пунктирному пути; имя верхнего
  уровня в объекте `tools` оказывается занятым пространством.
- Обработчики прогресса фильтруют вызовы расширений: в журнал попадает
  только `fetch`, всё прочее остаётся за пределами интерфейса.
- Таймаут в `web.ts` жёсткий и не настраивается: 30 секунд на любой запрос.
- `json()` в `web.ts` бросает исключение разбора, а не возвращает ошибку
  вызывающему — внутри Code Mode это становится исключением исполнения.
