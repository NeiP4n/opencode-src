# core/src — models, providers and the service files of the core

## Purpose

This set of root files of `packages/core/src` describes how opencode knows the providers, what models they have and how a ready-to-request model is made out of a catalog record. Here also lie three model-independent services: the generation of one-off text, web search, file formatting and the normalization of the pictures.

## What's In This Folder

Thirteen root files of `src`: nine around the models (`provider`, `models-dev`, `model`, `variant`, `aisdk-native`, `aisdk`, `model-resolver`, `generate`, `app`) and four auxiliary ones (`agent`, `websearch`, `formatter`, `image`). All services are written on Effect: `Context.Service` + `Layer` + a node `makeLocationNode`/`makeGlobalNode` with explicit dependencies.

## Key Files

- `provider.ts` — the registry of the providers. The type `ID`, the prefix `aisdk:`, `packageName()` removes the prefix and fixes the old scope `@opencode-ai/ai/` → `@opencode/`; `builtins` is a map from ~50 native packages `@opencode/ai/providers/*` to a lazy `import()`; `loadPackage()` looks for the package, in its absence installs the root npm package via `Npm` and resolves the entrypoint. The service `Provider.Service` (`Editor`/`Interface`) holds a `Map<ID, Definition>`, counts `snapshot()` taking the integrations into account and publishes `Provider.Event.Updated`. Here too are the merging utilities: `mergeOverlay` (a deep merge of JSON objects), `mergeHeaders` (keys in lower case), `timeouts()` and `DEFAULT_TIMEOUT_MS = 300_000`, the parsing of `CORE_KEYS`/`PROVIDER_ONLY_KEYS`.
- `models-dev.ts` — the source of the model catalog. The priority: a local file (`options.file`) → the KV cache → the embedded snapshot `models-dev/snapshot.txt` → the network `https://models.opencode.ai/api.json`. `normalize()` turns a provider record into a `Snapshot { info, models, environment }`, expands `experimental.modes` into separate models with a mode suffix, `mergeCost()` merges the prices by the tiers, `supports()` builds a `Variant.Support` out of `reasoning_options`. The periodic `refresh()` every 5 minutes under `Semaphore.makeUnsafe(1)` compares the `bodyDigest` (sha256) and stays silent with the byte-for-byte same body. There is `catalogModelStatus` = alpha/beta/deprecated.
- `model.ts` — the catalog of the models above the providers. `Info`, `Ref`, `Capabilities`, `Cost` are re-exported from `@opencode/schema/model`; `mergeCapabilities()` completes the partial capabilities with the base. The service `Model.Service` is built on `State.create` with copy-on-write drafts (`WeakSet` on the maps and on the models). `read()` merges the provider `settings`/`headers`/`body` into the model, sorts by `time.released` and caches the result through a `WeakMap` for the unchanged models; `available()` = the enabled ones, `default()` = the requested or the first available, `small()` looks for the families `gpt-luna`, `gemini-flash-lite`, `gemini-flash`, `claude-haiku`. The helpers: `parse("provider/model")`, `compatibility()` (a string or `{ field }` → `reasoningField`).
- `variant.ts` — pure functions that build the reasoning variants (`effort`, `toggle`, `budget_tokens`) by the package and by `reasoning_options`. There are about 25 protocols: `openaiChat`, `openaiResponses`, `anthropicMessages`, `gemini`, `bedrockConverse`, `openrouter`, `nvidiaChat`, `workersAIChat`, `basetenChat`, `deepinfraChat`, `deepseekChat`, `moonshotChat`, `alibabaChat`/`alibabaMessages`, `zaiChat`/`zaiMessages`, `minimaxMessages`, `sapAICore`, `vercelGateway`, `cloudflareAIGateway`, `cohere` and others; the `PROTOCOLS` table maps the package into the protocol. The constants: `EFFORTS = ["low","medium","high"]`, `ANTHROPIC_OUTPUT_TOKEN_MAX = 32_000`, `ALIBABA_THINKING_BUDGET_MAX = 64_000`.
- `aisdk-native.ts` — the translation of the configuration from the AI SDK packages into the native ones. `PACKAGES` (`@ai-sdk/anthropic` → `@opencode/ai/providers/anthropic` and 16 more), `HOSTS` — a walk by `providerID` with `protocols(name)` (`chat`/`messages`/`responses`), `NATIVE` — the set of "already native". `rewrite()` mixes the overlays into `settings`/`headers`/`body` and into the variants; `native()` and `resolve()` decide what a specifier turns into. The separate translators: Bedrock (`bedrockSettings`, `bedrockThinking`, `bedrockRequest`), OpenRouter (`openRouterRequest` → `X-OpenRouter-Title`, `HTTP-Referer`, `X-Provider-API-Keys`). The validation of the input is the schema `Legacy` on `StructWithRest` with `lenient()` fields.
- `aisdk.ts` — the bridge to the AI SDK. `locationLayer` gives the `Interface`: the hooks `hook.sdk`/`hook.language` (the registration with `Scope.addFinalizer`), the cache of the language models by `cacheKey` (the functions are serialized as `function:N`), `language()` and `model()`. `prepareOptions()` removes `headerTimeout`, `chunkTimeout`, `compaction`, `transport` from the settings and substitutes its own `options.fetch`: a header timer, `AbortSignal.any` from the signals, the merging of the request body via `mergeOverlay`, the `wrapSSE` wrapper for the timeout between the SSE chunks. `modelFromLanguage()` assembles an `AnyRoute` with `protocol: "ai-sdk"`, `sanitizer: "none"`, `auth: Auth.none`, an `endpoint` on `https://ai-sdk.local`, and `streamLanguage()` translates `LanguageModelV3StreamPart` into an `LLMEvent`, watching the open text/reasoning fragments. There is the recognition of the network errors (`NETWORK_ERROR_CODES`, `NETWORK_ERROR_MESSAGES`, `networkFailure` with a depth of 4) and the parsing of the provider errors (`decodeProviderError`).
- `model-resolver.ts` — turns a catalog choice into a ready `LanguageModel`. `withVariant()` lays the variant overlay on without changing the snapshot, `fromCatalogModel()` validates: the package is supported, `${VAR}` in the `baseURL` have resolved (otherwise `UnresolvedProviderVariablesError`), and the policy `compaction: "native"` does not promise what the route cannot do (`UnsupportedCompactionError`). `nativeCredentialSettings()` puts the key where the package expects it: `apiKey`, `authToken` for anthropic, `accessToken` for google-vertex. `layer` depends on Provider, Model, Integration, Npm, AISDK; with a provider `activation: "enabled"`, the absence of a credential and an API-key authorization the route is switched to `Auth.none`.
- `generate.ts` — a one-off text generation without a session. `Service.text({ prompt, model? })`: resolves the model through `ModelResolver`, sends `LLM.request` with the header `x-opencode-session` (the gateways require the attribution), translates the errors into `ModelSelectionError` or `UnavailableError`.
- `app.ts` — the metadata of the application: `Info { name, version, channel }`, `Context.Reference` with the default `opencode/unknown/unknown`, `useragent()` of the form `opencode/{channel}/{version}/{name}`, a global `node`.
- `agent.ts` — the catalog of the agents on `State.create`. `defaultID = "build"`. When an agent is created, four `external_directory` allows are added to the default permissions for the global data directories, `shell/*/*`, `tool-output/*`, tmp and config. `selectedDefault()` skips the agents with `mode === "subagent"` and `hidden`; `list()` puts the chosen one first; `select()` without an argument falls back to `build`, even if there is no agent.
- `websearch.ts` — the choice and the call of a web search provider. The choice is stored in the KV under the key `websearch:provider` and can be `false` (switched off), `"random"` or a concrete ID. In the `random` mode the binding to the session `preferred` and the cooldown on HTTP 429 work: the duration is taken from `retry-after` (seconds, a date or 60 seconds by default). The `preferred` cell is cleaned by the events `SessionEvent.Deleted` and `SessionEvent.Moved`.
- `formatter.ts` — the launch of a formatter by the file extension. `file(filepath)` takes `path.extname`, for each match resolves the command (`formatter.enabled` can return an array of arguments or `false`), substitutes `$FILE` and launches the process in `location.directory` with `extendEnv: true`. The commands are cached in a `WeakMap` by the formatter object. Success — the code 0, otherwise the log and an attempt of the next formatter.
- `image.ts` — the normalization of the pictures before sending. The default limits: autoResize is on, 2000×2000, 5 MiB in base64. The adapter `image/photon.js` is loaded lazily and once (`Effect.cached`), on a failure of the import — `ResizerUnavailableError`. The errors: `DecodeError` and `SizeError` with the actual and the limit sizes in the message.

## Important Details

- The separation of "core" and "provider": `nativeSettings()` throws away `chunkTimeout`, `compaction`, `fetch`, `headerTimeout`, `timeout`, `transport` — the native packages do not read them; `modelSettings()` also removes the `transport`-related keys when merging into the model.
- The timeouts of the transport, and not of the package: `model-resolver` moves `Provider.timeouts(configured)` into `defaults.http` via `mergeHttpOptions`, and not into the settings of the package.
- `mergeHeaders` compares the header names without regard to the case, therefore `Content-Type` and `content-type` are one key.
- `mergeOverlay` in the absence of a base or an overlay decodes the value as a JSON record and can return `undefined` if the record is empty; the nested objects are merged recursively, the scalars are overridden.
- Copying on write: `provider.ts` and `model.ts` do not mutate the shared definitions — the maps and the models are copied before the first edit, the result is `freeze(..., true)` (immer). In `provider.models.update` there is a separate protection against the frozen (already published) model.
- `cacheKey` in `aisdk.ts` is deterministic by the content of the settings; two functions with the same body get different ids, the same function — one.
- `models-dev.ts` decodes the embedded snapshot once per isolate (`bundledCache`), because the snapshot takes several MiB and one isolate can serve many runtimes. A write into the KV never brings down the load — the error is only logged as a warning.
- `variant.ts` has no state: the same input always gives the same variants; `budgets()` reduces the ceiling by one relative to `model.limit.output` and returns an empty list if the maximum is not positive.
- `aisdk.ts` cannot replay the native compaction of the provider and forward the media references (`source.type === "ref"`): both situations give an explicit error, and not a silent loss.
- The media from the result of a tool (the pictures and the PDFs) `aisdk.ts` takes out of `tool-result` and attaches as a separate user message with the text `Attached media from tool result:`; if no other parts are left, the text `Media attached in the following user message.` is inserted.
- `websearch.ts` at `choice === "random"` with all the providers in the cooldown returns the error of the last one, and does not raise a new request; `default()` in this mode chooses nothing, in order not to open the consent anew.

## Connections

- `models-dev.ts` → `variant.ts` (`Variant.resolve`) and `aisdk-native.ts` (`AISDKNative.native`): the catalog snapshot already carries the ready variants and the native packages.
- `provider.ts` → `aisdk-native.ts`: `Editor.update` and `models.update` pass every edit through `AISDKNative.rewrite`, therefore a manual setting cannot leave an AI SDK package behind.
- `provider.ts` → `integration.ts`, `credential.ts`, `bus.ts`, `location.ts`; `model.ts` → `provider.ts`, `bus.ts`, `state.ts`, `location.ts`.
- `model-resolver.ts` → `model.ts` (the catalog and the variants), `provider.ts` (`loadPackage`, the merging of the settings), `integration.ts` (the active connection and the credential), `npm` (the installation of the package), `aisdk.ts` (`loadAISDK`).
- `aisdk.ts` → `model.ts` (only the `ID` and `RuntimeInfo` types), `provider.ts` (`isAISDK`, `packageName`, `timeouts`, `mergeOverlay`), `state.ts`, the packages `@opencode/ai`, `@ai-sdk/provider`.
- `generate.ts` → `model-resolver.ts` and `@opencode/ai` (`LLMClient.generate`), plus `effect/app-node-platform.ts` for the LLM client.
- `agent.ts` → `bus.ts`, `state.ts`, `global.ts`; `formatter.ts` → `location.ts`, `app-node-platform.ts` (`AppProcess`); `image.ts` → `filesystem.ts`, `state.ts`; `websearch.ts` → `bus.ts`, `kv.ts`, `state.ts` and the session events.

## Pitfalls

- `Provider.packageName()` is needed almost everywhere: the prefix `aisdk:` cannot be compared with a package directly, and the old `@opencode-ai/ai/...` from the user config is fixed only by this function.
- The list `builtins` in `provider.ts` and the table `PROTOCOLS` in `variant.ts` are manual: a new native package without an entry in the first one will not load, and without an entry in the second one it will not get the reasoning variants.
- `model.package`, `model.modelID` and `model.id` are different things: `id` is the catalog record (it is shown and stored), `modelID` is the identifier in the API of the provider. In `model-resolver.ts` this is also recorded in the comments to `Resolved.model` and `Resolved.ref`.
- The errors of `model-resolver.ts` are named with the prefix `SessionRunnerModel.` — when searching by the tag it is not obvious.
- The `ai-sdk` routes use `sanitizer: "none"`: the sanitizers of the model families are switched off, the conversion of the tool schemas is done by the provider itself.
- `AISDK.language()` caches the model for a long time: a change of the settings without a change of the `cacheKey` will give the old model; the key includes `providerID`, `canonical`, `id`, `modelID`, `package`, `settings`, `headers`, `body`, `limit`.
- `HttpClient.filterStatusOk` in `models-dev.ts` stands before `retryTransient`: an answer without an OK status will get into the retry, and not into the parsing.
- `Image` without the adapter `image/photon.js` falls on any `normalize`, even if the file is small and no resize is needed: the check of the import is not lazy by the size.
- `Formatter.file` returns `true` only at the code 0; a formatter that prints into stdout works with `stdout: "ignore"` and will not see the output.
- `Agent.list()` changes the order — the chosen agent is always the first, so the list cannot be compared with the original order of the config.
