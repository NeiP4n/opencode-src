# core/permission — сохранённые разрешения пользователя по проектам

## Что в папке

- `sql.ts` — таблица `permission` с уникальным индексом по тройке проект+действие+ресурс.
- `saved.ts` — Effect-сервис `PermissionSaved`: список, добавление и удаление сохранённых разрешений.

## Ключевые файлы

- `packages/core/src/permission/saved.ts` — `Service`, `layer`, `node`, схемы входов `ListInput`, `AddInput`.
- `packages/core/src/permission/sql.ts` — `PermissionTable`.

## Важные детали

- Таблица `permission`: `id` (тип `PermissionSaved.ID` из `packages/schema/src/permission-saved.ts`), `project_id` — `.notNull()` со ссылкой на `ProjectTable.id` и `onDelete: "cascade"`, `action`, `resource`, плюс `Timestamps`.
- Уникальный индекс `permission_project_action_resource_idx` на `(project_id, action, resource)` — это и есть семантика «сохранить разрешение»: повторное сохранение той же тройки не создаёт вторую строку.
- `add` делает по одной строке на каждый элемент `input.resources` и завершает вставку через `.onConflictDoNothing()`. Из этого следуют два свойства: пустой массив ресурсов даёт пустую вставку (в коде стоит ранний выход), а конфликт по уникальному индексу проглатывается без ошибки.
- Каждая строка получает собственное `ID.create()`, а не один общий ID на вызов: удалять сохранённое разрешение можно по ID конкретного ресурса.
- `remove(id)` удаляет строго одну строку по `id` — операция без проверки проекта и действия.
- `list` без `projectID` возвращает все строки таблицы: условие `where` подставляется только когда `projectID` задан. Выборка по одному проекту — это уже фильтр, а не требование.
- Все запросы заканчиваются `.pipe(Effect.orDie)`: ошибка базы превращается в дефект, а не в типизированный отказ, поэтому у вызывающего нет ветки для «не удалось прочитать».
- Сервис собирается через `makeGlobalNode({ service, layer, deps: [Database.node] })` — глобальный узел, живущий на всё приложение, в отличие от узлов с областью location.
- `ID` и `Info` в модуле не свои: это переэкспорты из `packages/schema/src/permission-saved.ts`.

## Связи

- `packages/core/src/permission/sql.ts` — импортирует `ProjectTable` из `packages/core/src/project/sql.ts` ради внешнего ключа и `Project.ID` из `packages/schema/src/project.ts`.
- `packages/core/src/permission.ts` — корневой модуль: живой движок проверки разрешений. Поиск по `PermissionTable` даёт только `saved.ts` и сам `sql.ts`, то есть таблицу читает сервис сохранённых разрешений, а не движок проверки.
- `packages/core/src/database/database.ts` — сервис `Database`, отдающий соединение, которое использует `layer`.
- `packages/core/src/config/plugin/agent.ts` — приводит правила разрешений агентов из конфига к виду `Permission.Ruleset`, то есть к той форме, которую этот сервис хранит.

## Ловушки

- `list` без `projectID` читает всю таблицу, а не «текущий проект». Фильтр надо задавать явно.
- Конфликт вставки не виден вызывающему: `onConflictDoNothing` превращает повторное сохранение в молчание. Проверить, что разрешение сохранено, можно только последующим `list`.
- `remove` не проверяет проект: ID, полученный из другого источника, удалит строку чужого проекта.
- Ранний выход в `add` при пустом `resources` означает, что вызов без ресурсов не создаёт записи и не сообщает об этом.
- `Effect.orDie` на всех операциях: база недоступна — это дефект процесса, а не отказ, который вызывающий мог бы обработать.
