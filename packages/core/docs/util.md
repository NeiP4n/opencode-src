# core/util — короткие помощники без состояния: ошибки, оценка токенов, пути, glob-подстановки

## Что в папке

- `error.ts` — базовый класс именованных ошибок со схемой данных и фабрикой `create`.
- `error-summary.ts` — свёртка цепочки `cause` в короткий список для интерфейса.
- `token.ts` — грубая оценка числа токенов по длине текста.
- `slug.ts` — генератор человекочитаемых имён вида «прилагательное-существительное».
- `wildcard.ts` — сравнение строки с шаблоном, где `*` и `?` работают как в glob.
- `which.ts` — поиск исполняемого файла в `PATH` с учётом регистра имён переменных на Windows.
- `git-executable.ts` — выбор имени или полного пути к `git`.
- `lazy.ts` — мемоизация значения, вычисляемого один раз.
- `iife.ts` — однострочная обёртка для вызова функции без логики вокруг.
- Ни одного из этих файлов нет в отдельном пакете `@opencode/util`: одноимённая папка ядра и пакет — разные вещи.

## Ключевые файлы

- `packages/core/src/util/error.ts` — `NamedError`, `create`, `createSchemaClass`, `Unknown`.
- `packages/core/src/util/error-summary.ts` — `from`.

## Важные детали

- `NamedError` требует от наследника двух методов: `schema()` возвращает схему, `toObject()` — `{ name, data }`. Данные ошибки не хранятся в свободном виде: класс всегда строится вокруг схемы Effect.
- `create(name, data)` принимает либо набор полей, либо готовую схему, и всегда оборачивает их в `Schema.Struct({ name: Schema.Literal(name), data })`. У получившегося класса есть `Schema`, `EffectSchema`, статический `tag`, переопределённое имя и предикат `isInstance`.
- `isInstance` и `hasName` работают по строковому `name`, а не по `instanceof`: ошибка, пересекающая границу процесса или восстановленная из JSON, всё равно опознаётся. Цена этого решения — две ошибки с одинаковым именем неразличимы.
- Имя класса задаётся дважды: `Object.defineProperty(result, "name", { value: name })` меняет имя функции-класса, чтобы стектрейсы читались, а `public override readonly name = name` — имя экземпляра.
- `NamedError.Unknown` — уже готовый класс с полями `message` и необязательным `ref`.
- `ErrorSummary.from` декодирует ошибку `Schema.decodeUnknownOption` по схеме, где **все** поля необязательны. Поэтому чужая ошибка не ломает разбор: если декодирование не удалось, обход цепочки останавливается (`if (Option.isNone(result)) break`).
- Обход ограничен тремя способами сразу: не больше 8 записей, защита от цикла через `Set` уже посещённых объектов и остановка на первом недекодируемом значении.
- Тип записи берётся как `_tag` (тегированные ошибки Effect), затем `error.name`, затем `name` из декодированной структуры, и только потом строковое `"unknown"`.
- Стектрейсы в сводку не попадают намеренно — это комментарий в коде. Размер каждой записи не ограничен, ограничено только их число.
- `Wildcard.match` приводит и вход, и шаблон к прямому слэшу, экранирует специальные символы регулярного выражения, кроме `*` и `?`, и превращает их в `.*` и `.`. Флаги регулярного выражения — `si` на Windows и `s` на остальных платформах: без `i` сравнение регистрозависимо на всех платформах кроме Windows.
- Особый случай в шаблоне: хвост `" .*"` превращается в `"( .*)?"`. То есть шаблон, заканчивающийся пробелом и звездочкой, допускает и пустой хвост, и хвост с пробелом — а не просто любой суффикс.
- Регулярное выражение собирается заново на каждый вызов `match`, результат не кэшируется.
- `Token.estimate` делит длину строки на 4 и округляет, отрицательные значения невозможны из-за `Math.max(0, ...)`. Это оценка для интерфейса, а не счётчик токенов модели.
- `Slug.create` соединяет одно прилагательное из 29 и одно существительное из 35 через дефис. Списки объявлены `as const`, поэтому новые слова видны типам; конкретный генератор псевдослучаен через `Math.random()` и не сеется.
- `which` собирает путь поиска сам: берёт `PATH` или `Path` из переданного окружения, иначе из `process.env`, и добавляет `bin` через `path.delimiter`, если он задан. `PATHEXT`/`PathExt` обрабатываются так же. Вызов `whichPkg.sync` идёт с `nothrow: true`, то есть отсутствие исполняемого файла даёт `null`, а не исключение.
- `gitExecutable` вычисляется один раз при импорте модуля. На Windows это абсолютный путь (через `which("git")`), на остальных платформах — строка `"git"`. Функция `resolveGitExecutable` вынесена отдельно и чиста: её можно вызывать с произвольной платформой и произвольным результатом `which` в тестах.
- `lazy` различает «не вычислено» и «вычислено в `undefined`» отдельным флагом `loaded`. Без него значение `undefined` пересчитывалось бы при каждом вызове.
- `iife(fn)` просто вызывает `fn()`. Смысл только в читаемости: вызов в выражении, где блок невозможен.

## Связи

- `packages/util/src/fs-util.ts` и пакет `@opencode/util` — соседний служебный слой с похожими помощниками (хэш, глобальные пути, effect-хелперы). Папка `packages/core/src/util` не пересекается с ним по файлам.
- `packages/core/src/config/discovery.ts` — использует `FSUtil.contains` при фильтрации найденных конфигов; похожая по смыслу проверка вложенности написана здесь не в `match`.
- `packages/core/src/id/id.ts` — соседняя по назначению папка: генерация идентификаторов, тоже маленькая и самодостаточная.
- `packages/core/src/database/schema.sql.ts` — потребитель `packages/core/src/util/error.ts` там, где ошибки доступа к базе строятся через фабрику `NamedError.create`.
- `packages/core/src/v1/config/error.ts` — пример ошибки, несущей в данных путь и сообщение (`InvalidError` используется в `packages/core/src/config/variable.ts`).

## Ловушки

- `NamedError.hasName` и `isInstance` опознают ошибку по имени строкой. Ошибка с тем же именем из другого пакета будет принята за свою — и данные у неё другой формы.
- `ErrorSummary.from` останавливается на первой недекодируемой ссылке в цепочке. Если у внешней ошибки нет ни одного из перечисленных полей, сводка окажется пустой, хотя ошибка вложена глубже.
- `ErrorSummary.from` обрезает цепочку на 8 записей. При глубокой вложке отказы дальше восьмого не попадут ни в какой диагностический вывод.
- `Wildcard.match` не экранирует `*` и `?` при разборе, они всегда become операторы. Экранировать их в шаблоне нельзя: символа экранирования здесь не существует, а `\` приводится к `/`.
- Флаг `i` у `match` включается только на Windows. Один и тот же шаблон совпадёт с ресурсом по-разному на разных платформах — это осознанно, но легко пропустить.
- `Token.estimate` завышает или занижает оценку для любого языка с многобайтовыми символами: считается длина в кодах JS, а не в байтах и не в токенах модели.
- `gitExecutable` фиксируется при импорте. Изменение `PATH` или `PATHEXT` позже в процессе на этот модуль не подействует.
- `lazy` кэширует и исключение: если `fn` бросит, значение не запомнится, но вычисление запустится снова при следующем вызове. Кэшируется только успешный результат.
